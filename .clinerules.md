# Next.js & React Independent Station Development Rules

## 1. Environment & Browser Testing Priorities
- Whenever modifying UI components or pages, you MUST use the `browser_action` tool to navigate to `http://localhost:3000` (or the actual dev port) to verify the visual result.
- Do not ask the user for screenshots. Use the browser tool to take screenshots and analyze the layout yourself.
- Check the Chrome Console logs via the browser tool to ensure there are no React Hydration errors, uncaught runtime errors, or 404s for assets/APIs.

## 2. Next.js Architecture Constraints
- **App Router Compliance**: Always check if the file is under the `app/` directory. By default, treat components as Server Components unless interactivity (`useState`, `useEffect`, `useContext`) is strictly required.
- **Client Components**: If interactivity is needed, you MUST prepend the `"use_client"` directive at the very top of the file before any imports.
- **Hydration Error Prevention**: When rendering client-side specific content (like local dates, local currency, browser screen size, or localStorage), wrap them in a `mounted` state check using `useEffect` to prevent SSR mismatch.

## 3. Independent E-commerce Critical Paths
- **Cart & Checkout**: Any changes to `/components/Cart` or Checkout components must ensure that client-side states (e.g., Zustand, Redux, or React Context) synchronize correctly with browser cookies/localStorage.
- **Tailwind CSS & Styling**: When updating UI, use existing Tailwind CSS patterns. Do not inject inline styles that overwrite the global theme unless requested. Ensure components are responsive and mobile-friendly by default.
- **API & Fetching**: Use appropriate caching and revalidation strategies (e.g., `fetch` with tags/revalidate or SWR) for product catalogs to prevent stale prices during testing.

## 4. Agent Execution Loop Goal
- Your mission is to deliver fully functional, error-free UI code. 
- Iterate, test via the browser, read console logs, and fix any self-introduced bugs automatically. 
- Present the final screenshot link to the user only after confirming that the feature works perfectly on the live local preview.
